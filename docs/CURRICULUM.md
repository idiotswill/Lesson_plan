# Skills and coverage — v0.2.1

This is a compact introductory chapter with ten activities and guided teaching. It is not a complete learning programme or a validated mastery assessment.

## Activities

| Stable activity ID | Learning target | Game action | Check |
|---|---|---|---|
| `set-union` | Include members of either or both sets without duplicates | Invite fireflies | Exact set equality on a new numerical example |
| `set-intersection` | Require membership in both sets | Select shared fireflies | Exact intersection |
| `set-difference` | Distinguish A minus B from B minus A | Exclude one flower's guests from the other's | Directed difference |
| `set-complement` | Use the stated universal set | Select the outsiders | Complement relative to U |
| `py-energy` | Assign an arithmetic result based on inputs | Calculate Pip's energy | Several input cases; a changed unit rate in check mode |
| `py-decision` | Combine Boolean conditions and use strict inequality | Decide whether Pip flies | Boolean output, equality boundary, uncharged case |
| `py-loop` | Repeat, accumulate, update a counter and stop | Budget a sequence of lanterns | Several stop counts including zero/one; loop syntax and outputs |
| `web-structure` | Separate a tab title from a visible heading and paragraph | Name the observatory's page | Rendered document structure and visible elements |
| `web-links` | Match a fragment link to a unique destination | Give stars directions | Link text, href and target id |
| `web-css` | Use one class rule for colour and inner spacing | Light two paper beacons | Computed colour and padding on both elements |

## Teach before asking

Each activity introduces notation or syntax, demonstrates a method, offers smaller guided actions with explanations, and then opens the full experiment. Across the chapter there are ten walkthroughs and 27 guided tasks. Help can be replayed, paused or skipped.

The sequence introduces membership before set operations, expressions before decisions and loops, and document structure before links and styling. Sets are explained one element at a time. Python worked frames show values AFTER the highlighted instruction; the learner-program trace instead records BEFORE-line events and labels that distinction. HTML practice begins with one editable paragraph. CSS names selectors, properties and values before asking for a rule.

Walkthrough completion is a checkpoint, not skill evidence. Revealing an answer is permitted and does not unlock a lantern. Full experiment submissions create progress; supported work is kept distinct from fresh checks without in-app help.

## Implementation boundaries

All executable programming tasks use Python 3. Inputs are supplied as variables rather than interactive prompts. Numeric and Boolean outputs are checked across multiple cases. Requiring loop syntax plus successful outputs does not prove understanding or prevent dead-code workarounds; this is a single-player practice tool, not an anti-cheating system.

Web examples use quoted attributes and id-based destinations. The preview intentionally supports a limited set of HTML/CSS. It does not validate all markup, accessibility or cascade behaviour. The padding exercise covers one-value inner spacing, not a full layout system.

## Not implemented

Math beyond the introductory sets sequence, including broader number systems, complex numbers, matrices, determinants, linear systems, vectors and transformations, remains future work. Functions, collection types, larger programs and broader debugging are also not complete. Web layouts, images, tables, forms, responsive design and larger projects remain future work.

Logic circuits and computing have reserved map destinations but no playable activities. A label or placeholder is not an implemented lesson.

## Evidence limits

Generated set variations currently retain two elements in each Venn region, even though the checker handles empty sets. Varied cardinalities, subsets, empty intersections and symbolic expressions should be included before claiming broader transfer.

Fresh checks mostly change parameters and are not validated transfer measures. A later-check label uses at least 24 hours between successful fresh checks; this is not a complete spaced-practice scheduler. The app cannot detect outside help.

Automated tests check specified examples and software behaviour. They do not establish that a beginner understands a method, retains it, or enjoys learning it. Before expanding, ask the learner to explain a method and solve a new problem without copying the demonstration.
